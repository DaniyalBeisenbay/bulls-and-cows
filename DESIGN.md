# Архитектура Bulls and Cows

## Границы и структуры данных

`src/core/` не импортирует DOM, время, localStorage или UI. Функции работают с аргументами и возвращают значения. Секрет и попытка — строки: ведущий ноль не теряется, hex сравнивается после `toLowerCase()`.

`Settings`, `Game`, `Entry`, `ScoreRecord` в `src/core/state.ts` имеют readonly-поля. История — `readonly Entry[]`. `submitGuess` создаёт новый объект и массив `[...game.history, entry]`; старые записи разделяются между версиями, потому что не изменяются. При неверной, повторной или послепобедной попытке возвращается исходное состояние. `createGame` копирует настройки. TypeScript readonly обеспечивает ограничения на этапе компиляции; runtime-тест замораживает исходные данные и проверяет отсутствие мутаций.

Запись рекорда хранит число попыток, миллисекунды, дату и параметры раунда. Общая таблица ограничена десятью записями. `addRecord` сортирует копию: сначала попытки, затем время. UI показывает систему и длину у каждого результата. `parseRecords` проверяет недоверенные данные из хранилища и отбрасывает некорректные записи.

Побочные эффекты сосредоточены в `src/main.ts`: чтение часов, DOM, события и localStorage. Время передаётся в ядро числом, источник случайности — функцией. `generateSecret` детерминирован при детерминированном переданном источнике; default `Math.random` и stateful PRNG сами по себе не являются чистыми. Инъекция позволяет отделить этот эффект и повторяемо тестировать алгоритм. Мемоизация использует приватный Map: внутренний кеш меняется, наблюдаемый результат зависит только от аргументов.

## Алгоритмы

- `createDigitValidator(base)` фиксирует алфавит в замыкании и возвращает предикат символа. Это частичное применение параметра base (фабрика каррированного валидатора). Предикат используется в `isValidGuess` и в обработчиках `beforeinput`/`input` в `renderGame`.
- `isValidGuess` проверяет параметры, длину, каждый символ через `every` и отсутствие повторов через `Set`. Hex нормализуется до проверки повторов: `aA` недопустимо.
- `generateSecret` рекурсивно выбирает индекс из оставшегося алфавита и передаёт дальше новый массив без выбранной цифры. На каждом шаге размер уменьшается: повторов и бесконечного ожидания уникальной цифры нет. Нулю разрешено быть первым. Источник обязан возвращать конечное значение в [0, 1).
- `evaluateGuess` считает быков через `filter`. Два `reduce` строят частотные словари без мутаций; ещё один суммирует минимум частот для общих цифр. Коровы — общие совпадения минус быки. Частоты дополнительно предотвращают двойной подсчёт при передаче повторяющихся цифр напрямую в функцию.
- `countPossibleSecrets` проверяет внешние аргументы и вызывает мемоизированную рекурсию `P(b,l) = b × P(b−1,l−1)`, `P(b,0) = 1`. Рекурсивный помощник допускает внутренние base 1 и 0, необходимые для полного алфавита. Ключ кеша содержит оба параметра. Ошибочные аргументы не кешируются.

## Сложность

Обозначения: l — длина кода, b — размер алфавита, k — количество различных цифр. В приложении l ≤ 6, b ≤ 16. Оценки ниже показывают зависимость от параметров, даже если реальные границы малы.

| Функция                | Время                                      | Дополнительная память | Обоснование                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | O(l × b)                                   | O(l × b)              | На каждом из l шагов `filter` копирует оставшийся алфавит. Рекурсивные кадры удерживают предыдущие массивы. Конкатенация строк даёт O(l²), что укладывается в O(l × b), поскольку l ≤ b.        |
| `evaluateGuess`        | O(l × k), для цифр O(l)                    | O(l + k)              | Копирование частотного объекта при `reduce` стоит O(k), k ≤ 16 для поддерживаемых цифр. `filter` и суммирование линейны. Для произвольного растущего алфавита нельзя заявлять безусловное O(l). |
| `isValidGuess`         | O(l × b), для фиксированного алфавита O(l) | O(l)                  | Проход `every`; предикат делает `includes` по алфавиту длиной b ≤ 16. Создание `Set` в среднем O(l).                                                                                            |
| `countPossibleSecrets` | O(l) при холодном кеше, O(1) при попадании | O(l) для нового пути  | l рекурсивных умножений и кешируемых подзадач, стек глубины l. Суммарное пространство кеша O(B²), если вызывать все допустимые сочетания до максимального base B.                               |

## Чистый код: конкретные применения

- Единственная ответственность: `validator.ts` определяет допустимые символы, `guess.ts` проверяет попытку, `evaluate.ts` считает совпадения, `state.ts` описывает переходы состояния, `main.ts` связывает их с браузером.
- Говорящие имена: `startedAt`, `elapsedMs`, `validSettings`, `parseRecords` обозначают смысл и единицы измерения, вместо общих `data` и `process`.
- Ранние возвраты: `submitGuess` сразу отбрасывает запрещённые переходы; основной путь остаётся линейным.
- Повторное использование: единый `createDigitValidator` не позволяет правилам ввода расходиться с правилами ядра; `validSettings` используется при старте и чтении рекордов.
- Малые функции: отдельные `renderSettings`, `renderGame`, `renderHistory`, `renderRecords`; `el` создаёт DOM с `textContent`, без HTML-инъекций.
- Явные зависимости: часы и random передаются ядру, поэтому тесты не ждут таймеров и не зависят от браузерного хранилища.

## TDD и FIRST

Для пяти обязательных функций сохранены отдельные пары `test:` → `feat:`. Тестовые коммиты проверялись до создания импортируемого модуля и завершались ошибкой отсутствующего модуля; следующий коммит добавлял реализацию и запускался только после зелёного набора. Аналогичная пара есть для состояния игры. Это настоящие промежуточные красные состояния, а не восстановленная задним числом история.

Тесты быстры (без сети, браузера и ожиданий), независимы, повторяемы (фиксированные random и timestamps), самопроверяемы (`expect`) и написаны раньше реализации. Мемоизация проверяется на стабильность значений; наличие кеша и рекурсивного вызова подтверждается кодом, тест не привязан к внутреннему Map.

`pre-commit` запускает только lint-staged, поэтому разрешает красный тестовый коммит. `pre-push` запускает `npm test`. `--passWithNoTests` разрешает начальный tooling-коммит без тестов. Общая проверка включает ESLint, Prettier и строгую компиляцию TypeScript.
